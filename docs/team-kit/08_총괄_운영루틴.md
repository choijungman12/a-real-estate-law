# 08. 총괄 운영 루틴
> 붙여 넣는 곳: 총괄 대화에 전체를 붙이고 「메모로 저장해라」. 「## 」 하나 = 메모 하나.

## routine-progress-check
*「진행상황」을 받으면 — 노션 + GitHub를 같이 보고 한 장으로*

1. 작업 DB: `상태 ≠ 완료` 전부 + 최근 완료(메모 · 마지막 수정 시각).
2. GitHub: `gh pr list --state all --limit 8`, 작업 브랜치가 main보다 앞선 커밋(`git log origin/main..origin/<브랜치>`), 마지막 커밋 시각.
3. 열린 PR이 있으면 검사 상태 확인 → 통과면 바로 검수 · 머지(routine-merge).
4. 보고 형식: 결론 한 줄 → 표(작업 · 상태 · 마지막 움직임) → 남은 것과 예상 시간 → 운영자가 할 일(있을 때만).
5. `진행 중`인데 3시간 넘게 레코드 수정도 커밋도 없으면 「멈춘 것 같음」+ 깨우기 한 줄. 단, 클라우드 세션은 로컬 작업 트리에서 일하며 PR 때만 올리기도 하니, 레코드의 최근 진행 기록도 같이 본다.

## routine-merge
*PR 머지 — 검사 통과 + 직접 확인 뒤*

1. `gh pr view N --json isDraft,mergeStateStatus,statusCheckRollup` → 초안 아님 · CLEAN · 검사 성공.
2. 검사 표시가 비어 있으면 배포 기록으로 확인: `gh api repos/<org>/<repo>/deployments?sha=<head>` → statuses `success`. 그래도 모르면 로컬에서 `npm ci && npm run build && npm run lint && npx tsc --noEmit`.
3. `gh pr merge N --merge`(브랜치 유지). 이슈가 닫혔는지 확인.
4. 머지 뒤 로컬 main을 받아 빌드 → 미리보기 서버 → 바뀐 화면을 실제 크기로 직접 본다(routine-verify).
5. 문제가 있으면 보완 레코드 + 이슈(rule-new-fix-record). 되돌릴 정도로 크면 운영자에게 먼저 알린다.

## routine-verify
*화면 검수 — 직접 띄워 보기*

- 미리보기(launch.json의 fe)를 띄우고 실제 쓰는 크기(예: 1920×1080, 모바일 375)로 맞춘다. 로그인이 필요하면 로컬 테스트 값만 쓴다(운영 사이트에는 비밀번호를 넣지 않는다).
- 지시의 합격 기준을 한 줄씩: 보이나 · 눌리나 · 글이 읽히나(배경 위 대비) · 겹치거나 가려지지 않나 · 오류 0(콘솔) · 늦게 뜨지 않나.
- 성능 · 움직임은 저장소의 측정 스크립트(헤드리스)로 숫자를 낸다. 미리보기 탭이 숨겨져 있으면(`document.hidden`) 그리기가 멈춰 느려 보이니, 그때는 헤드리스 측정으로 판단한다.
- 결과를 레코드에 「총괄 확인 M/D: O/△/X + 근거」로 적는다.

## routine-new-work
*새 일을 받았을 때 — 레코드 나누기*

1. 목표 · 범위 · 마감을 한 줄씩 정리(애매하면 상식으로 정하고 적음).
2. 담당별로 나누되 **겹치지 않게**: 같은 파일 · 폴더를 동시에 고치는 두 레코드를 동시에 「다음」으로 두지 않는다.
3. 레코드 본문: `## 지시` 아래 목표 · 범위 · 합격 기준 표 · 하지 말 것 · 참고(파일 경로 · 시안 · 이슈) · 결과 형식.
4. 코드 일은 GitHub 이슈(라벨 · 마일스톤)를 만들고 레코드 ↔ 이슈를 서로 링크.
5. 순서: 바로 할 것만 `다음`, 나머지 `시작 전` 또는 `대기`(무엇을 기다리는지 메모).
6. 로컬 직원은 깨운다, 클라우드 직원은 레코드가 「다음」이면 스스로 가져간다(멈춰 있으면 운영자에게 깨우기 한 줄 부탁).

## routine-parallel
*병렬 — 겹치지 않는 일끼리, 한 세션 안에서도 가능*

- 운영자가 「병렬로」라고 하면: 코드 폴더 기준으로 줄을 나눈다(예: 줄 A = 3D/화면 핵심, 줄 B = 로그인 · 관리자 · 독립 기능). 레코드 이름 끝에 `(줄 A)` · `(줄 B)`.
- 한 클라우드 세션이 서브 에이전트 두 개 + 각자 git worktree로 동시에 진행할 수 있다. 세션이 지정 브랜치 하나에만 올릴 수 있으면, 끝난 묶음마다 그 브랜치에 합쳐 PR(본문에 줄별로 나눠 적고 Closes 각각).
- 저장소 CLAUDE.md 「병렬 줄」 칸에 표(줄 · 맡는 폴더 · 레코드 순서)와 규칙(상대 폴더 수정 금지 · 공유 파일은 최소 · PR 전 main 합치기)을 넣는다.
- 한 줄이 먼저 끝나면 다른 줄의 겹치지 않는 일을 넘겨받게 해 쉬는 줄이 없게 한다.

## routine-deadline
*마감 — 거꾸로 일정 짜기*

- 운영자가 마감을 주면: 코드 마감(마감보다 앞) → 총괄 확인 → 고칠 것만 → 완료. 우선순위 ①②③을 정하고, 다듬기(전체 점검 · 미세 조정)는 마감 뒤로 미룬다.
- 저장소 CLAUDE.md 「마감」 칸 + 해당 레코드 본문에 같은 내용을 넣는다. 「끝나는 대로 바로 PR」로 바꿔 총괄이 미리미리 머지 · 확인한다.
- 마감 시각이 바뀌면 CLAUDE.md · 레코드 · 메모를 모두 같이 고친다.
- 늦어질 기미가 보이면 미리 「늦으면 무엇을 미룰지」를 운영자에게 한 줄로 알린다.

## routine-report-style
*운영자에게 보고하는 방식*

- 결론 먼저(첫 문장에 답). 그다음 표 하나. 내가 직접 확인한 것과 직원 보고만 본 것을 구분한다.
- 운영자가 할 일은 맨 끝에 따로, 복사해서 붙일 문장은 코드 블록으로.
- 문제가 생기면(내 실수 포함) 숨기지 말고 그대로 말하고 다음 조치를 붙인다.

## routine-handover
*다른 PC · 다른 사람에게 넘길 때*

- 총괄 메모(기억) 전체를 주제별 md로 묶어 다운로드 폴더에 만든다(규칙 · 운영 · 프로젝트 현황 · 스킬). 비밀값 제외.
- 받는 쪽은 새 총괄 대화에 붙여 「메모로 저장해라」 → `/team-chief`.
